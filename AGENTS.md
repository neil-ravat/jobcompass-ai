# JobCompass working agreement

- Use real permitted API listings from Day 1. Synthetic responses belong only
  in unit tests. No fabricated application seeds or fallback jobs.
- The user has authorized Codex to implement core functions, superseding the
  initial independent-coding mentorship restriction. Build one milestone at a
  time; keep the code explainable for the user's later study.
- After completing or attempting any major milestone, produce a clean Markdown
  Milestone Handoff Report that can be pasted into a separate ChatGPT Project
  Milestone Manager conversation. Save a copy in the repository and give the
  report to the user before advancing to another milestone.
- Every report must include: project and milestone ID; planned requirements;
  implemented behavior; created/modified files; important functions, classes,
  API endpoints and database changes; actual test commands and results; bugs,
  incomplete features and limitations; architecture decisions and tradeoffs;
  user-written versus Codex-generated work; interview concepts; exact next
  milestone and recommended task. Include real commit hashes/file references
  where available. End with a section titled "Evidence Needed for Verification".
- Do not fabricate tests, results, metrics, deployments, or commits. File
  existence alone does not demonstrate working behavior. Distinguish offline
  checks, live verification, and work that remains unverified.
- Current milestone details and deadlines are in IMPLEMENTATION_PLAN.md.
- The 17 November project-manager directive authorizes autonomous progression
  through API/ranking, PostgreSQL/semantic retrieval, optional LLM workflow, and
  evaluation/delivery. Deliver a report after each phase before proceeding;
  a separate approval is not required when acceptance passes. Record blockers
  and continue valuable independent work. Create local commits at verified
  checkpoints, excluding secrets/runtime data; do not push.
